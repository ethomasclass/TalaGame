Tala, Four Ways

The same girl, the same outline — sampled from the game’s own Tala — handed to four different renderers. The first is what the game draws today. The other three are plain JavaScript on a canvas, no libraries, nothing a school laptop can’t run offline.

B and C move on their own. Watch for a blink.

What actually changes in JavaScript

  • A character becomes data; a style becomes a renderer. All four panels draw one outline. Pick a style later and the cast doesn’t have to be redrawn.
  • Expressions stop being swapped pictures. Today a frown is a different <use> element. In code a brow is an angle and a mouth is a curve, so faces can ease from one expression into the next.
  • The school-laptop rules still hold. One file, offline, Canvas 2D only. I didn’t build a WebGL watercolour version: it’s lovely, and it depends on GPU support older Chromebooks and locked-down machines don’t always have.
  • “Heavy” and “light” are how these techniques are known to behave, not measurements on your machines. One timed run on a real school laptop settles it.

What I’d do

B for the game. It keeps every character you’ve already approved, swaps the costliest part of the renderer for the cheapest, and gives the whole cast the “movement beyond eyes” you asked for early on.

C for the moments that are memories — the title card, the establishing shots, Lola’s polaroid.

D belongs on paper, not on screen: it’s the fieldbook’s look, not the game’s.
